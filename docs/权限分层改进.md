## 六类业务身份与21项指标

| 业务身份 | 指标权限 | 机构权限 |
|---|---|---|
| 总行管理层 | ZB001～ZB021 | 全部机构 |
| 分支行管理层 | ZB001～ZB021 | 账号配置机构 |
| 业务条线人员 | ZB003～ZB006、ZB018～ZB021 | 账号配置机构 |
| 风险合规人员 | ZB013～ZB017 | 全部机构 |
| 财务人员 | ZB001～ZB002、ZB007～ZB012 | 全部机构 |
| 系统管理员 | 无业务指标 | 仅系统管理与审计 |

现有 `viewer / analyst / admin` 保留为技术角色，新增 `business_role` 承载上述六类身份，避免重构全部前端和历史接口。

## 已实施的执行链

```text
自然语言问题
→ 生成 QueryPlan
→ 校验岗位指标白名单和机构范围
→ 建立 DuckDB 临时权限视图
→ SQL 安全校验与 EXPLAIN 预检
→ 只读执行
→ 返回结果或按角色动态脱敏
```

权限拒绝发生在 SQL 预检和执行前。分支行与业务条线账号即使生成了无 `WHERE` 的 SQL，数据库临时视图也只暴露其授权机构和指标；限定名绕过会被 SQLGuard 拒绝。

## 动态脱敏和导出

- ZB013～ZB017 定义为 S3 敏感指标；无对应明文权限的查看者，其结果字段统一显示为 `***`，避免通过列别名或计算字段绕过脱敏。
- 系统管理员可以查看查询元数据和审计，但结果记录全部脱敏、SQL不返回，并禁止问数、导出和分享。
- 单次和批量导出统一经过后端权限检查；超过200行必须二次确认。

## 审计与告警

- 审计覆盖问题提交、查询计划与SQL、查询结果行数、历史查看、下钻、导出、分享、失败和越权。
- 审计事件通过 `previous_hash + event_hash` 形成 SHA-256 哈希链，并保存事件数和链头锚点，可检测内容修改、链路断裂和尾部删除。
- 已实现七条最小告警规则：S3高频查询、10分钟3次越权并冻结15分钟、单次导出超过200行、当日累计导出超过1000行、非工作时间导出S3、10分钟创建3个分享链接、单次查询超过8个指标。
- 管理员可通过 `/api/v1/admin/alerts` 查看、确认和关闭告警；管理页显示待处置告警及审计链状态。

## 当前边界

- 当前数据只有 `日期 + 指标 + 机构 + 指标值`，没有客户、客户经理、身份证或手机号字段，因此第一版的“行级”落实到机构数据行，不能虚构“本人管户”范围。
- 当前无个人敏感列，列级控制落实为指标白名单和量化结果动态脱敏；后续接入客户明细表时再增加字段分类与手机号、身份证专用掩码。
- 局部机构账号暂不支持全省排名和省均值类跨机构计算，避免在过滤后返回错误排名；后续可建设只参与安全计算、不暴露其他机构明细的安全聚合服务。
- SQLite 哈希链属于本地防篡改检测，不等同于监管级 WORM 存储；生产环境应将审计链头同步到外部不可变存储。
- 当前告警计数和去重按单进程最简演示实现；多 worker、多实例生产部署需改为数据库事务或集中式风控服务。
- README中的默认账号、默认口令和内存令牌只供比赛演示；生产环境必须接入统一身份认证并更换全部口令。
- 分享链接只作为限时定位令牌，查看者仍须登录，并按查看者当前岗位和机构权限重新鉴权；旧匿名接口固定关闭。
